# OpenMontage-Muse

把 OpenMontage 的 agentic 视频生产思想，跑在 AI 助手原生工具链上。
原版的上游仓库（只读参考）放在 `upstream/`，生产流程不依赖它。

## 能力映射（替代原版 provider 层）

| 原版环节 | 原版 provider（需 key/付费） | 本方案替代 | 说明 |
|---|---|---|---|
| 视频片段生成 | Veo / Kling / MiniMax（fal.ai 等） | `自带视频生成` | 文本生视频或图生视频；**每条用户消息最多 6 个成功视频**（含转交给 subagent 生成的），分镜时按 ≤6 个场景规划；**计入你的 AI 助手订阅配额，非无限免费** |
| 关键帧/静态素材 | FLUX / GPT Image / Imagen | `自带图片生成` | 每条消息最多 4 张；图生视频更可控，先出关键帧再转视频；同样计入订阅配额 |
| 配音/旁白 | ElevenLabs / Google TTS / Chirp | Fish Audio `bin/tts.py` | 免费模型 s2.1-pro-free（$0，免费至 2026-11-30）；5 个实测中文音色见下；长文案分段合成再用 ffmpeg 拼接 |
| 剪辑合成 | Remotion / Python composer | `ffmpeg` | 拼接、混音、字幕、转码，本机已验证可用 |
| 免费素材路线 | Pexels / Pixabay | 可选（需 key）；默认直接用 media 生成 | 二选一 |

## Fish Audio 免费档配置（key 相关）

- 免费模型 `s2.1-pro-free`：$0/百万字节，限时免费至 2026-11-30，无 SLA、受公平使用约束。
- **Key 已由用户经 安全凭证库 接入**（凭证名 `custom.fish-audio`），调用时通过 surrogate 机制自动注入 Authorization 头；**永远不要让用户在聊天里贴 key**，也不要把 key 写进任何文件、日志、记忆。
- 如果合成返回 401/403：先确认请求真的走了 helper（没走 helper 就是没带凭证）；确认带上仍被拒绝，再用 `credentials.request_api_access`（带 `reconnect`）让用户重连。
- 真人克隆类音色（AD学姐等）商用有肖像权风险，公开分发前必须提醒用户。

## 生产管线

先跑 `scripts/preflight.sh`（换环境或隔段时间后必跑），再 `scripts/new_run.sh <主题>` 建任务目录。

1. **idea**：明确主题、时长、横/竖屏、有无旁白。输出一句话 brief（讲什么、给谁看、什么风格）。
2. **script**：写分镜脚本：场景列表 = 每个场景的画面描述 prompt + 时长 + 旁白文案。
3. **sample（必做）**：先只生成 **1 个样片**（1 个视频片段 + 1 段旁白，合成小样）→ 发给用户看 → 用户批准后再批量生产。不直接一次生成全部镜头。
4. **reference（可选）**：用户发视频文件，或给 YouTube/TikTok/Reel 链接（"做个类似的"）→ 先做参考拆解，再出差异化版本（不做 1:1 搬运：版权风险 + 平台会去重）。按下面三级链路拿素材，**拿到哪一级就用哪一级，不要在拿不到的环节反复重试**：
   - ① 用户发的视频文件（最可靠）：`ffmpeg -i` 看时长/编码 → 抽帧看画面 → 有内嵌字幕轨道直接读（`ffmpeg -map 0:s`）；没有字幕就请用户提供文案文本，不要自己脑补台词；
   - ② 公开链接（YouTube 等）：先 `browser.open` 取页面文本（标题/描述，免费免登录）；再 `yt-dlp --skip-download --print "%(title)s | %(duration_string)s" --write-auto-sub --sub-langs "zh.*,en.*" <url>` 拿元数据+自动字幕（没装就 `pip install yt-dlp`，`preflight.sh` 会检查）。字幕拿到就用，拿不到就按"标题+描述+用户补充"拆解，缺文案直接问用户要；
   - ③ 登录墙平台（TikTok/Reel/小红书等多半拿不到内容）：**直接请用户发视频文件或文案**，不要反复尝试绕过；
   - 输出拆解报告（固定 8 项）：主题一句话 / 目标受众 / 前 3 秒钩子 / 结构分段（含每段时长） / 节奏（镜头数、平均镜头时长） / 风格（画面、音乐、字幕样式） / 为什么火（一条判断） / 3 个差异化创意（换主题 / 换视角 / 换风格）；
   - 用户选定一个创意后，进入正常管线（从第 1 步 idea 重新开始）。
5. **asset**：按场景逐个生成，全部落到 run 目录的 `assets/`，并在 `shots.json` 里逐镜头记账：
   - `自带视频生成`：prompt 写具体画面描述（主体、动作、场景、镜头、氛围）；视频子代理会自动扩写，**不要自己加电影感修辞**；`output_dir` 指到 assets 目录；
   - 旁白：`scripts/speak.sh "文案" <音色名> out.mp3`（长文案先分段，合成后用 ffmpeg 拼成一条音轨）；
   - **配额记账**：`shots.json` 的 `quota.videos_used` 每次成功生成后 +1；**样片和重生成都计入**，不是只算场景数。`videos_used` 到 6 就停，剩下的拆到下一条消息。
6. **compose**：`scripts/compose.sh`（ffmpeg）：规格统一（1280x720@30fps，可改）→ 按分镜顺序拼接 → 混入旁白（旁白更长时自动循环画面铺满，不再静默截断）→ 可选叠加字幕 → 输出终版 mp4。无声片段会自动补静音轨。
7. **review**：看一遍成片（ffprobe 查时长 / 抽帧看画面），检查字幕、节奏、音画对齐；有问题只重做对应镜头（`shots.json` 里该镜头标 `failed`），不整批重来。

## 恢复

- `shots.json` 是任务的唯一状态源：每个镜头的 `status`（pending/sample/done/failed）、`clip` 路径、`snapshot_id` 都记在里面；中断后从这里恢复，失败只重做对应镜头。
- `DECISIONS.md` append-only：重要决策（换音色、改分镜、大改创意）先跟用户确认再执行，只追加不改历史。

## 硬约束

- 每条用户消息视频配额 6 个、图片 4 个：生产前先算好，**样片+重生成都算**；超了就拆多次对话。转交 subagent 做视频也要在指令里写明它能用几个。
- 费用真相（对外不要再说"全程零费用"）：① 视频/图片片段走 AI 助手原生视频生成能力，**计入你的 AI 助手订阅配额**，每条消息 6 视频/4 图片是硬上限，大批量生产要分多条消息；② 配音走 Fish Audio `s2.1-pro-free` **免费档，仅限时免费至 2026-11-30**，无 SLA、受公平使用约束，过期后按官方定价（付费档 $15/百万字节）；③ ffmpeg 本地合成真正零费用。"无需第三方付费 key"只在免费档有效期内成立。
- 真人克隆类音色（AD学姐等）商用有肖像权风险，公开分发前必须提醒用户。
